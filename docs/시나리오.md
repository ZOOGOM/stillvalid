### 왜 영어인가
- 행사 제출 문서가 영어이고 심사위원도 영어 사용자일 가능성이 높습니다.
- **영어 사용자가 한국어 공고를 읽는 장면**은 심사위원 본인이 한국어를 못 읽는다는 점 때문에 설명 없이도 효과가 전달됩니다.
- 10개 표시 언어 기능은 화면을 한국어·아랍어로 바꾸는 장면으로 따로 보여줍니다.

## 1. 핵심 메시지

> **"Saved a notice. Still the same?"**
> StillValid checks a saved notice against the official page, shows what changed with the exact quotes, and refuses to confirm when it can't prove it's the same notice.

장면마다 이 세 가지 중 하나를 보여줍니다.
1. **Changed, with proof**: 바뀐 값과 양쪽 원문 인용
2. **In your language, without rewriting the facts**: 화면 언어는 바꾸되 날짜·기관명·인용은 원문 그대로
3. **Honest when unsure**: 동일성이 불확실하면 확정하지 않음

## 2. 제작 원칙: AI가 만드는 것과 실제 화면

**제품이 하는 일은 실제 앱 화면으로만 보여줍니다.** 결과 판정, 바뀐 값, 인용, 진행 단계를 AI 모션그래픽으로 새로 그리면 "작동하는 앱"이 아니라 "작동하는 것처럼 보이는 영상"이 됩니다.

| 요소 | 만드는 방법 | 쓰는 장면 |
| --- | --- | --- |
| **실제 앱 화면** | 프로덕션에 실제 요청을 보내는 브라우저 자동 녹화(모바일 뷰포트 390×844). 사진 업로드부터 결과까지 실제로 실행 | 3–12번 |
| **AI 모션그래픽** | 도입부, 장면 전환, 오른쪽 자막 패널, 확대 강조, 엔딩 카드, 구조도 | 1–2, 13번, 전 구간 콜아웃 |
| **AI 내레이션** | TTS 영어 음성 1개로 통일. 대본은 5절 | 전 구간 |
| **AI 일러스트** | Alex 캐릭터와 서울 거리 등 도입부 배경. 실존 인물을 닮지 않은 양식화된 캐릭터로 만들고, 실제 기관 로고는 쓰지 않음 | 1–2번 |

### 정직성 표시 (필수)
- 도입부 AI 장면: 모서리에 *Illustrative animation*
- 앱 화면 구간 첫 등장: *Live app, recorded in a mobile browser*. 실제 iPhone 촬영이 아니므로 **iPhone이라고 쓰지 않고**, 기기 프레임도 특정 제품이 아닌 단순한 휴대폰 모양을 씁니다
- 대기 구간: *Real wait ≈ N s · sped up*. 녹화에서 잰 실제 시간을 넣습니다
- 8번: *Demo card: date altered for this demo. The official page says 3 April.*
- 10번: 앱의 **Synthetic example · No live lookup** 배너가 잘리지 않게 합니다
- 엔딩 또는 설명란: *Narration and motion graphics generated with AI tools*
- 쓰지 않을 표현: "always accurate", "never miss", "works for any notice worldwide". 사람이 정답을 확인한 실제 공고 정확도 평가는 아직 0건입니다.

## 3. 여행자 장면 설계

### 페르소나
**Alex**: 서울을 방문 중인 영어 사용자. 한국어를 읽지 못합니다. 며칠 전 거리 게시물을 휴대폰으로 찍어 두었습니다. 도입부에서는 AI 일러스트 캐릭터로만 등장합니다.

### 여행자에게 실제로 작동하는 기능 (모두 현재 앱에 있음)
| 여행자 상황 | 앱 동작 | 화면 문구 (EN) |
| --- | --- | --- |
| 공고가 모르는 언어로 되어 있음 | 공고 언어는 따로 감지하고, 결과는 내 표시 언어로 보여줌 | Display language: English |
| 휴대폰은 본국 설정, 공고는 현지 것 | 사용 지역과 공고 국가를 따로 다루고, 다르면 확인을 요청 | *Your region of use differs from the country read in this notice.* → **Use the notice country** |
| 현지 직원에게 보여줘야 함 | 날짜·주소·기관명·인용은 번역하지 않고 원문 그대로 유지 | See the supporting text |
| GPS·위치 제공이 꺼림칙함 | 위치는 선택. 쓰더라도 좌표를 서버로 보내지 않음 | Region of use (optional) |

### 공고 선택: Plan A / Plan B
- **Plan A (기본, 검증됨):** 서울시 공지 [nttNo=454731](https://www.seoul.go.kr/news/news_notice.do?nttNo=454731)을 바탕으로 마감일을 일부러 앞당긴 재구성 카드 이미지(*Demo card* 표시)를 씁니다.
  - `d46ab66` 프로덕션 리허설에서 `changed`, verified가 나왔습니다(`3. 31.(화) 15:00` → `4. 3.(금) 15:00`, 비교 25.2초).
  - 이 공지는 관광 정보가 아니라 시 공지입니다. 그래서 내레이션은 "여행자를 위한 공고"라고 하지 않고 **"visitors and newcomers"가 공통으로 겪는 상황**으로 말합니다.
- **Plan B (관광 공고로 교체, 리허설 통과 시에만):** 등록된 공식 도메인의 여행자용 공고로 교체합니다. 후보는 `nps.gov` 공원 알림·폐쇄, `britishmuseum.org` 전시·운영 시간, `london.gov.uk` 행사, `seoul.go.kr` 축제·행사, `si.edu` 박물관 운영입니다.
  - 통과 조건: ① HTML 페이지(PDF·첨부·스크립트 전용 제외) ② 한 페이지에 한 프로그램만 있거나 섹션 제목으로 구분됨 ③ 연도가 포함된 날짜 ④ 리허설 2회 연속 verified
  - 하나라도 어긋나면 Plan A를 그대로 씁니다.
  - 참고: 사용자가 iPhone으로 찍은 축제 공고는 비등록 도메인이라 `review`로 끝났고 약 3분이 걸렸습니다. 이 경로는 쓰지 않습니다.

## 6. 화면 구성과 4K 60fps 규격

### 출력 규격
| 항목 | 값 |
| --- | --- |
| 해상도 | 3840×2160, 정사각 픽셀 |
| 프레임 | **60.00fps 고정**(가변 프레임 금지). 모든 소스를 60fps로 맞춤 |
| 마스터 파일 | ProRes 422 HQ 또는 H.264 무손실에 가까운 설정(CRF 10 이하). 편집 중 재압축은 한 번만 |
| 업로드 파일 | H.264 High, 4K60, 약 60Mbps(YouTube 4K60 SDR 권장 범위), 색 공간 BT.709, `yuv420p`. 3분 기준 약 1.3GB |
| 예비 파일 | 1920×1080 60fps, 약 12Mbps. 제출 폼에 용량 제한이 있거나 업로드가 실패할 때 사용 |
| 오디오 | AAC 48kHz 스테레오 320kbps, 통합 음량 약 −14 LUFS, 피크 −1 dBTP |

### 4K 기준 크기
| 요소 | 크기 |
| --- | --- |
| 바깥 여백(타이틀 세이프) | 좌우 192px, 상하 108px |
| 하단 자막 | 글자 높이 약 96px, 최대 2줄, 하단에서 216px 위 |
| 오른쪽 패널 장면 제목 | 약 140px |
| 오른쪽 패널 핵심 값(before → after) | 약 220px |
| 정직성 주석 | 약 64px, 화면에 최소 3초 유지 |
| 휴대폰 화면 | 높이 약 1944px(캔버스의 90%) × 폭 약 898px(390:844 비율) |

### 앱 화면 해상도
- **연속 동작 녹화(3–7, 10–12번):** 모바일 뷰포트 390×844를 기기 배율 3배로 렌더링해 **1170×2532, 60fps**로 녹화합니다. 4K 캔버스의 휴대폰 화면(높이 1944px)보다 커서 그대로 넣으면 축소만 일어나고, 1.3배 확대까지는 화질이 유지됩니다.
- **확대 장면(5, 8, 9번):** 해당 순간의 화면을 기기 배율 6배 정지 이미지(2340×5064)로 따로 캡처하고, 편집기에서 천천히 확대·이동합니다. 정지된 실제 화면을 움직이는 것이므로 내용은 녹화와 같습니다. 캡처는 반드시 같은 녹화 실행에서 같은 결과 화면으로 합니다.
- 연속 녹화는 브라우저를 가상 디스플레이에 띄우고 화면 자체를 60fps로 캡처하는 방식으로 합니다. 일반적인 브라우저 자동화 녹화 기능은 프레임이 낮고 화질이 떨어져 4K60에 맞지 않습니다. 로컬에서의 구체적인 방법은 12절에 있습니다.

- 자막은 하단 안전영역(아래 10%) 안에 두고, 휴대폰 화면 위로 겹치지 않게 합니다.

## 12. 1170×2532 60fps 앱 화면 캡처 방법

Mac 화면을 직접 녹화하면 Retina 배율(2배) 때문에 390×844 화면이 780×1688로만 잡히고, 3배(1170×2532)로 띄우면 노트북 화면 높이를 넘습니다. 그래서 화면 크기에 묶이지 않는 방식을 씁니다.

| 순위 | 방식 | 장점 | 주의 |
| --- | --- | --- | --- |
| **1 (권장)** | **Docker 리눅스 컨테이너 + Xvfb + Chromium(`--force-device-scale-factor=3`) + `ffmpeg x11grab` 60fps** | 해상도가 정확히 1170×2532로 고정되고, Mac·Windows 어디서나 같음 | 소프트웨어 렌더링이라 CPU를 많이 씀. 시험 캡처에서 빠진 프레임 확인 필수 |
| 2 | Chromium 헤드리스 + CDP 화면 스트림(PNG 프레임 + 타임스탬프) → `ffmpeg`로 60fps 고정 영상 재구성 | 디스플레이 불필요 | 화면이 바뀔 때만 프레임이 나오므로 전환 애니메이션은 60fps보다 덜 부드러울 수 있음 |
| 3 | Mac 브라우저 + OBS 60fps 창 캡처 | 익숙한 도구 | 세로로 돌린 외부 모니터가 있어야 3배 해상도가 나옴 |

**권장 방식의 캡처 설정(시험 캡처로 확정)**
- 가상 화면: 1170×2532, 24비트
- 브라우저: 창 안쪽 크기 390×844, 기기 배율 3, 주소창·탭 없는 앱 창 모드, 한 번에 한 탭
- 캡처: 60fps, H.264 `crf 12`, `preset ultrafast`, `yuv444p` 중간 파일(합성 단계에서 `yuv420p`로 변환)
- 통과 기준: 10초 캡처가 정확히 600프레임이고, `ffmpeg` 로그에 중복·누락 프레임 경고가 거의 없음. 실패하면 `crf`를 올리거나 Docker에 CPU를 더 할당합니다

### 사실 표시 원칙
- 위성 텍스처는 **공개 저작권 해제 자료**만 씁니다: NASA Blue Marble(낮), NASA Black Marble(밤 불빛). 도시 단위로 확대할 때는 Copernicus Sentinel-2처럼 출처 표기 조건의 무료 자료를 씁니다. Google·상용 위성 사진은 쓰지 않습니다. 출처는 엔딩이나 설명란에 적습니다
- 비행 경로는 **연출**이므로 화면 구석에 *Illustrative* 표시를 둡니다
- 지도 위에 "전 세계 공고를 확인한다"는 인상을 주는 핀을 여러 도시에 찍지 않습니다. 249개 지역 선택은 전 세계 공고를 확인할 수 있다는 근거가 아닙니다. 굳이 핀을 넣는다면, 앱에 실제로 **등록된 공식 도메인이 있는 곳**(서울, 런던, 뉴욕, 워싱턴 DC, 샌프란시스코 등)만 *Registered official sources today*라는 제목으로 표시합니다

### Promptfilm으로 가능한 것과 확인할 것
| 항목 | 상태 |
| --- | --- |
| 16:9 3D 지구본, 카메라 하강, 텍스처 | 가능. 기존 예제(우주 스케일 영상)에 NASA Blue Marble 지구 텍스처를 쓴 코드 패턴이 있음 |
| 60fps | 가능. 기본 최종 렌더가 60fps, 프레임 단위로 정확함 |
| **4K(3840×2160)** | **기본 기능 아님.** 최종 렌더는 16:9일 때 1920×1080 고정입니다. 플러그인 렌더러가 화면 배율 설정을 이미 지원하므로, 배율 2로 캡처하는 작은 래퍼 스크립트로 4K를 낼 수 있을 것으로 보입니다. **시험 렌더로 확인 필요.** 안 되면 1080p를 4K로 늘리지 않고 이 안을 접습니다 |
| 자막 | Promptfilm 자막은 끄고(`--text0`) 영상 전체 자막은 합성 단계에서 넣습니다. 자막 모양이 영상 내내 같아야 하기 때문입니다 |
| 카메라 속도 | Promptfilm은 초당 줌 속도에 상한이 있습니다. 지구 전체(약 12,000km)에서 서울(약 30km)까지는 최소 약 2초가 필요해 4–5초 하강이면 여유 있습니다 |
| 품질 검사 | Promptfilm은 자동 QA, 별도 시각 검토, 출고 판정(READY)을 통과해야 최종 렌더를 허용합니다. 이 과정이 시간을 씁니다 |

### 시간 영향
- 예상 추가 시간 **3–4시간**(조사·스토리보드 30분, 제작 1.5–2시간, QA·검토 1시간, 4K 렌더 수십 분). 15절의 6번(모션그래픽 2시간)을 대체하므로 실제 순증은 약 1–2시간입니다
- 마감이 빠듯하므로 진행 조건을 둡니다: **4K 시험 렌더가 30분 안에 성공**하고, **앱 녹화(15절 3–4번)가 먼저 끝났을 때**만 진행합니다. 둘 중 하나라도 어긋나면 14절의 2D 일러스트안으로 돌아갑니다
