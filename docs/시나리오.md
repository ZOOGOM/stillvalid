### 왜 영어인가
- 행사 제출 문서가 영어이고 심사위원도 영어 사용자일 가능성이 높습니다.
- **영어 사용자가 한국어 공고를 읽는 장면**은 심사위원 본인이 한국어를 못 읽는다는 점 때문에 설명 없이도 효과가 전달됩니다.
- 10개 표시 언어 기능은 화면을 한국어·아랍어로 바꾸는 장면으로 따로 보여줍니다.

## 1. 핵심 메시지

> **"Saved a notice. Still the same?"**
> StillValid checks a saved notice against the official page, shows what changed with the exact quotes, and refuses to confirm when it can't prove it's the same notice.

장면마다 이 세 가지 중 하나를 보여줍니다.
1. **Changed, with proof**: 바뀐 값과 양쪽 원문 인용
2. **In your language, without rewriting the facts**: 화면 언어는 바꾸되 날짜·기관명·인용은 원문 그대로
3. **Honest when unsure**: 동일성이 불확실하면 확정하지 않음

## 2. 제작 원칙: AI가 만드는 것과 실제 화면

**제품이 하는 일은 실제 앱 화면으로만 보여줍니다.** 결과 판정, 바뀐 값, 인용, 진행 단계를 AI가 새로 그리면 "작동하는 앱"이 아니라 "작동하는 것처럼 보이는 영상"이 됩니다.

| 요소 | 만드는 방법 | 쓰는 곳 |
| --- | --- | --- |
| **실제 앱 화면(영상)** | 프로덕션에 실제 요청을 보내는 브라우저 자동 녹화, 60fps | IN 구간 전체 |
| **실제 앱 화면(정지 이미지)** | 같은 녹화 실행에서 찍은 고해상도 캡처. 3D 휴대폰 화면의 텍스처와, OUT 구간에서 튀어나오는 결과 카드로 사용. **잘라내기만 하고 내용은 고치지 않음** | 3D 구간의 휴대폰 화면, OUT 구간 |
| **3D 모션그래픽(Promptfilm)** | 지구, 서울 하강, 여행자 테이블, 휴대폰, 화면 속으로 들어가기·나오기, 엔딩 | 3D·OUT 구간 |
| **AI 내레이션** | TTS 영어 음성 1개로 통일. 대본은 6절 | 전 구간 |
| **자막·콜아웃** | 합성 단계에서 같은 글꼴로 넣음 | 전 구간 |

### 정직성 표시 (필수)
- 3D 장면 첫 등장: 모서리에 *Illustrative animation*
- IN 구간 첫 등장: *Live app, recorded in a mobile browser*. 실제 iPhone 촬영이 아니므로 **iPhone이라고 쓰지 않고**, 3D 휴대폰도 특정 제품을 닮지 않게 만듭니다
- OUT 구간: *Cards lifted from the live result screen*
- 대기 구간: *Real wait ≈ N s · sped up*. 녹화에서 잰 실제 시간을 넣습니다
- 결과 구간: *Demo card: date altered for this demo. The official page says 3 April.* 실제로 공고가 바뀐 사례처럼 말하지 않습니다
- 공고 시점: *Public notice from March 2026, used as an example · checked on <날짜>*. 접수가 이미 끝난 공고이므로 지금 신청할 수 있는 것처럼 보이지 않게 합니다
- 국가 선택 구간: *Country selected by the user*. 모델이 국가를 읽지 못해 직접 고른 경우에 붙입니다
- 합성 예제 구간: 앱의 **Synthetic example · No live lookup** 배너가 잘리지 않게 합니다
- 엔딩 또는 설명란: *Narration and motion graphics generated with AI tools*, 위성 영상 출처
- 쓰지 않을 표현: "always accurate", "never miss", "works for any notice worldwide". 사람이 정답을 확인한 실제 공고 정확도 평가는 아직 0건입니다.

## 4. 레이아웃 모드

| 모드 | 화면 | 소스 |
| --- | --- | --- |
| **3D** | Promptfilm 3D 장면. 지구 → 서울 → 여행자 테이블 위 휴대폰 | Promptfilm 렌더 |
| **IN** | 카메라가 휴대폰 화면 속으로 들어간 상태. **휴대폰 화면이 화면 높이 전체(2160px)를 채움**. 실제 앱이 움직이는 모습을 최대한 크게 보여줌 | 실제 앱 녹화 60fps |
| **OUT** | 결과가 나오면 카메라가 휴대폰 밖으로 빠져나오고, 결과 카드가 휴대폰 화면에서 3D 공간으로 떠오름 | Promptfilm 렌더 + 실제 결과 정지 이미지 |

### IN 모드 (4K)
```
┌──────────────────────────── 3840 × 2160 ────────────────────────────┐
│ 흐린 확장 배경 │                    │                                  │
│ (같은 화면을   │   실제 앱 화면       │   장면 제목 (약 140px)            │
│  크게 흐리고   │   높이 2160px       │   핵심 값 크게 (약 220px)          │
│  어둡게)       │   폭 약 998px        │   정직성 주석 (약 64px)            │
│               │   (390:844 비율)    │                                  │
│               │                    │   ── 자막 (약 96px, 최대 2줄) ──   │
└──────────────────────────────────────────────────────────────────────┘
   x ≈ 380–1380에 휴대폰 화면 · 오른쪽 약 2/3는 콜아웃과 자막
```
- 휴대폰 테두리는 화면 밖으로 나가 있어 보이지 않습니다. "휴대폰 안에 들어와 있다"는 느낌을 줍니다
- 양옆 빈 곳은 같은 녹화를 크게 확대해 흐리고 어둡게 깔아, 세로 화면이 가로 영상 안에서 비어 보이지 않게 합니다
- **확대(punch-in):** 영상 위 확대는 **1.15배까지**입니다(배율 3 캡처, 13절). 국가 불일치 배너와 결과처럼 더 크게 보여줄 곳은 정지 이미지로 대신합니다
- 자막은 오른쪽 영역 아래쪽에 둡니다. 휴대폰 화면 위에는 자막을 겹치지 않습니다

### IN ↔ 3D 전환 (들어가기·나오기)
- **들어가기:** 3D 휴대폰 화면에는 실제 녹화의 첫 프레임(앱 홈) 정지 이미지를 입힙니다. 카메라가 그 화면으로 다가가 IN 모드와 같은 크기·위치가 되는 순간 실제 녹화로 이어집니다(6프레임 교차 전환)
- **나오기:** 반대로, 녹화의 해당 프레임 정지 이미지가 입혀진 3D 휴대폰에서 카메라가 물러납니다

### OUT 모드 (결과 카드)
- 결과 화면이 IN 모드에서 1초 보인 뒤, 카메라가 휴대폰 밖으로 빠져나옵니다. 휴대폰은 테이블 위에 비스듬히 놓여 있고, 화면에는 실제 결과 정지 이미지가 보입니다
- 다음 카드가 화면에서 하나씩 떠올라 휴대폰 옆 공중에 나란히 섭니다. 모두 **같은 녹화 실행의 결과 화면을 잘라낸 것**입니다
  1. 판정: *We found a few changes*
  2. 변경 항목: Application deadline(*Your saved notice*와 *Retrieved material* 값, **Changed** 표시)
  3. *Your notice* 인용
  4. *Retrieved source* 인용
  5. 출처: *Registered institution domain*, 확인 시각
- 카드는 내레이션이 짚는 순서대로 떠오르고, 각 카드에 최소 2.5초 머뭅니다. 카드 내용은 잘라낸 그대로이며 글자를 다시 쓰거나 바꾸지 않습니다

## 13. 60fps 앱 화면 캡처 방법

**현재 선택(v12): 아래 표의 2순위 방식, 배율 3(1170×2532).** 이 PC에는 Docker와 WSL 배포판이 없어 1순위를 쓰지 않습니다. 시험 결과는 19절입니다.

Mac 화면을 직접 녹화하면 Retina 배율(2배) 때문에 390×844 화면이 780×1688로만 잡히고, 더 높은 배율로 띄우면 노트북 화면 높이를 넘습니다. 그래서 화면 크기에 묶이지 않는 방식을 씁니다.

| 순위 | 방식 | 장점 | 주의 |
| --- | --- | --- | --- |
| **1 (권장)** | **Docker 리눅스 컨테이너 + Xvfb + Chromium(`--force-device-scale-factor`) + `ffmpeg x11grab` 60fps** | 해상도가 정확히 고정되고, Mac·Windows 어디서나 같음 | 소프트웨어 렌더링이라 CPU를 많이 씀. 시험 캡처에서 빠진 프레임 확인 필수 |
| 2 | Chromium 헤드리스 + CDP 화면 스트림(PNG 프레임 + 타임스탬프) → `ffmpeg`로 60fps 고정 영상 재구성 | 디스플레이 불필요 | 화면이 바뀔 때만 프레임이 나오므로 전환 애니메이션은 덜 부드러울 수 있음 |
| 3 | Mac 브라우저 + OBS 60fps 창 캡처 | 익숙한 도구 | 세로로 돌린 외부 모니터가 있어야 고배율이 나옴 |

**해상도 선택 (IN 모드는 휴대폰 화면 높이 2160px)**
| 기기 배율 | 캡처 크기 | IN 모드 기본 크기에서 | 선명하게 확대 가능한 한계 |
| --- | --- | --- | --- |
| **4 (먼저 시험)** | 1560×3376 | 0.64배로 축소 | 약 1.5배 |
| 3 (예비) | 1170×2532 | 0.85배로 축소 | 약 1.15배 |

- 배율 4로 10초 시험 캡처를 먼저 하고, 프레임이 빠지면 배율 3으로 내립니다. 배율 3이면 IN 모드 확대는 1.15배까지만 쓰고, 더 큰 확대는 정지 이미지로 대신합니다
- 캡처 설정: 60fps, H.264 `crf 12`, `preset ultrafast`, `yuv444p` 중간 파일(합성 단계에서 `yuv420p`로 변환)
- 통과 기준: 10초 캡처가 정확히 600프레임이고, `ffmpeg` 로그에 중복·누락 프레임 경고가 거의 없음

### 15-2. 지켜야 할 것
- **위성 영상:** NASA Blue Marble(낮), NASA Black Marble(밤 불빛)처럼 저작권이 풀린 자료만 씁니다. 서울 확대에는 Copernicus Sentinel-2처럼 출처만 밝히면 되는 무료 자료를 씁니다. Google이나 상용 위성 사진은 쓰지 않고, 출처는 엔딩·설명란에 적습니다
- **비행 경로:** 연출이므로 *Illustrative* 표시를 둡니다
- **도시 핀:** 여러 도시에 핀을 찍어 "전 세계 공고를 확인한다"는 인상을 주지 않습니다. 249개 지역 선택은 전 세계 공고를 확인할 수 있다는 근거가 아닙니다
- **광화문 일대:** 실제 건물을 정밀하게 재현한 것처럼 보이게 하지 않습니다. 빛과 거리의 분위기만 표현합니다
- **휴대폰·소품:** 특정 제품(iPhone 등)이나 브랜드를 닮지 않게 만듭니다. 교통카드·지도에도 실제 로고를 넣지 않습니다
- **사람:** 등장시키지 않습니다

### 15-3. 카메라 속도
- Promptfilm에는 줌 속도 상한(초당 약 3 e-fold)이 있습니다. 지구 전체(약 12,000km)에서 서울(약 30km)까지는 최소 약 2초, 서울에서 테이블 높이(약 1m)까지 더 내려가려면 추가로 약 3.5초가 필요합니다. A 구간 20초 안에 충분히 들어갑니다

### 15-4. 4K 렌더 확인
- Promptfilm 최종 렌더는 16:9일 때 **1920×1080 고정**이고, 60fps는 기본 지원합니다
- 렌더러 내부에 화면 배율 설정이 있어서, 배율 2로 캡처하는 작은 래퍼 스크립트로 3840×2160을 낼 수 있을 것으로 보입니다. 플러그인 파일은 고치지 않습니다
- 8절 5번에서 3초 분량 시험 렌더로 확인합니다. 1080p를 4K로 늘리는 방법은 쓰지 않습니다

### 15-5. 4K 렌더가 안 될 때
- 3D 대신 2D 벡터·HTML 모션그래픽으로 같은 흐름을 만듭니다(지도 일러스트 → 테이블 위 휴대폰 → 화면 속으로 → 결과 카드가 떠오름). HTML은 4K60으로 프레임 단위 렌더링이 가능합니다
