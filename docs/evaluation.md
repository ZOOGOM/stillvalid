# Real-notice HTTP evaluation

`scripts/evaluate-live.mjs` exercises the deployed public HTTP contract without reading provider keys. The committed case template is intentionally empty. No real-notice accuracy measurements have been completed by adding this tool. Its local HTTP-fixture tests are harness checks, not Meta, Redis, source-fetch or notice-accuracy results.

Use Node.js 24. Before any external run, confirm the environment's network policy permits the deployment origin; do not bypass a denied host. Prepare public notices and independently reviewed official references in a private `.data/evaluation/` directory. Never commit photos, private notice text, cookie values or filled case files. The `.data/` tree is already gitignored.

```sh
# Validation only: no HTTP requests or model calls, even with populated cases.
node scripts/evaluate-live.mjs --url https://YOUR_DEPLOYMENT_HOST --cases .data/evaluation/cases.json --output .data/evaluation/dry-run.json

# Explicitly enables real HTTP requests and potentially billable inference.
node scripts/evaluate-live.mjs --url https://YOUR_DEPLOYMENT_HOST --cases .data/evaluation/cases.json --output .data/evaluation/run.json --execute

# Synthetic localhost HTTP contract tests; no provider calls.
node --test tests/live-evaluation.test.mjs
```

`--output` defaults to `.data/evaluation/report.json`; use a unique path per run to retain history. Existing output is overwritten. HTTP origins must be HTTPS, except loopback development servers. Redirects are rejected so cookies and input are not forwarded to another origin. `--fixture --execute` permits synthetic cases only against localhost/loopback, skips pacing and labels every record as an HTTP fixture with zero accuracy cases. Never point that mode at a local app configured with a real provider key: loopback does not itself imply mocked inference.

## Private case format

The root is `{ "version": 1, "cases": [...] }`, with at most ten cases per invocation. The empty committed template performs no calls and cannot execute. Each case has:

| Property          | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`              | Opaque unique identifier, 1–48 letters/digits/underscore/hyphen; do not use names or personal identifiers.                                                                                                                                                                                                                                                                                                                                                                          |
| `kind`            | `real` for an actual human-supplied notice; `synthetic` for fixtures. Non-fixture execution rejects synthetic inputs.                                                                                                                                                                                                                                                                                                                                                               |
| `lang`            | Result language: `ko`, `en`, `ja`, `zh`, `es`, `fr`, `de`, `pt`, `ar`, `ru`.                                                                                                                                                                                                                                                                                                                                                                                                        |
| `country`         | Optional nullable ISO country/region code; independent of language, nationality and residence. The server validates its supported list.                                                                                                                                                                                                                                                                                                                                             |
| `input.text`      | Original public notice text, maximum 18,000 characters.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `input.imagePath` | Optional PNG/JPEG/WebP path relative to the case JSON; read locally into a Base64 data URL in memory. Maximum 2,900,000 bytes. Text and image may be combined.                                                                                                                                                                                                                                                                                                                      |
| `sourceUrl`       | Optional official source URL. Omit it for a search-path evaluation. Supplying it bypasses discovery and must not be reported as a search success.                                                                                                                                                                                                                                                                                                                                   |
| `expectedStatus`  | Human-assigned `changed`, `matched`, `cancelled`, `expired`, `review` or `unavailable`.                                                                                                                                                                                                                                                                                                                                                                                             |
| `humanReference`  | `{ "url": "https://official.example/...", "checkedAt": "ISO timestamp", "reviewed": true }`, independently inspected by a human; never mark an unreviewed reference true.                                                                                                                                                                                                                                                                                                           |
| `expectedFields`  | Array of `{ "key", "before", "after", "beforeQuote", "afterQuote", "verified" }`. Keys are `deadline`, `date`, `location`, `status`, `cost`, `eligibility`. Values retain original source wording. `verified` defaults to `true`. New cancellations may have `before: null` and `beforeQuote: null`. Verified fields require a nonempty official `afterQuote`. For expected `review`/`unavailable` only, fields may explicitly require `verified: false` and nullable `afterQuote`. |

A real non-fixture case needs `expectedStatus` and a reviewed official `humanReference` to receive an accuracy verdict. Expected `review` and `unavailable` allow omitted or empty `expectedFields`: these produce `scoreScope: "status_only"`. This supports human-reviewed cases with no retrievable source, an ambiguous date or a different notice edition without inventing field values or quotations. The human must still independently determine the expected nondefinitive status and supply the reference; merely choosing a conservative label is not evidence.

Definitive `changed`, `matched`, `cancelled` and `expired` expectations require a nonempty list of verified field expectations and official quotations. They cannot pass on status alone. When fields are supplied for any status, values, expected verification flag and quotes must all match exactly. A nonnull after-quote must link to the human reference URL; a null after-quote on an explicitly unverified field checks absence of a quotation and does not assert official-source verification. These cases report `scoreScope: "status_and_expected_fields"`.

Cases without the required expectations remain operational checks and are not scored. The tool compares human-provided references to the app's output; it does not independently certify that the reference is official, current or correct. The expected field list should cover every material fact being evaluated. A passing verdict concerns only those supplied expectations. In particular, a status-only pass does not verify quotation safety, all field claims, the reason for abstaining or general correctness; review those separately. Synthetic cases and HTTP fixture mode are excluded from accuracy regardless of their expectations.

## Requests, limits and failure handling

The tool creates two distinct anonymous sessions through `GET /api/status`. It keeps cookies only in memory, checks live readiness and records public deployment SHA/model metadata if supplied. Each case calls `POST /api/extract`, then `POST /api/checks` using the extracted notice and a single stable request key for that attempt. It consumes incremental NDJSON, including UTF-8/chunk boundaries and an unterminated final line. A streamed error, absent result or demo result fails the case.

For each successful result it checks owner retrieval, foreign-session retrieval returning 404, foreign-session deletion returning 404, and continued owner access. Finally it deletes the owned result and checks 404. Known result IDs are also cleaned up after failures. If a network break occurs before a result ID is received, the tool cannot prove cleanup; use the application's session deletion/recovery flow, or wait for normal expiry. It does not silently retry uncertain work.

Calls are sequential, with at least seven seconds between billable POST starts in live mode, keeping this invocation below the shared ten-starts-per-rolling-minute limit. Other activity may still consume the same limits. HTTP 429, transport errors, streamed errors and failed operational checks stop the run without automatic retries. No budget-bypass option exists. A batch has at most ten extracts and ten checks; each check can make multiple provider requests, and these counts are **not** a monetary spending cap. Review the provider/hosting/storage budgets separately before execution. Re-running creates new attempts and may incur more charges.

The report records opaque case ID, language/input mode, public build/model metadata, actual status, reference-match booleans, accuracy verdict, elapsed wall time, isolation/deletion outcomes and sanitized failure category. It never records extracted text, images, cookie values, field contents, quotations, URLs from notices, provider bodies or keys. Cost and token usage are `not_measured` because the current API does not expose them. Measure those separately in the provider's billing system; never infer dollar cost from case count.

Search without `sourceUrl` is reported as requested with/without a failure warning; this is not proof that a discovery model returned an authoritative result. Review the official reference matches and actual app result separately. A `search` phase alone is not a success signal. `expiresAt` is metadata only: `ttlExpiry` remains `not_waited_or_verified`, because the tool does not wait 24 hours or test actual eviction. This flow checks individual deletion, not full-session deletion, real expiry or load/limit enforcement.

## Ten-notice evaluation and release evidence

Map the ten real-notice slots in [the acceptance checklist](acceptance.md) to opaque case IDs. For each slot, a human must supply the public notice/image, country (or explicitly unknown), result language, current official reference, expected status and material field/quote expectations. Include real changed/matched/cancelled/expired/ambiguous cases and cases with no source URL; select multiple languages based on actual notices, not translated synthetic placeholders. Keep a private worksheet associating each case ID with the independent review and reference date.

After a permitted live run, record each case's success/failure, verdict, elapsed time and deployment SHA in that worksheet. Keep operational success separate from accuracy; report accuracy denominator only from `scoredCases`, and do not combine fixture-test counts with real notices. A failed/deferred run is evidence of a limitation, never a substituted synthetic success. Refresh time-sensitive references before comparing a later run.

This tool does not establish physical-device photo quality, mobile Safari/Android behavior, full-session deletion, 24-hour expiry, externally measured costs, official competition rules, submission/video readiness, or worldwide source/language coverage. Actual photos, actual deployment networking, real provider inference/search/source comparison, hosted Redis behavior and human-reviewed notice accuracy remain separate evidence until run and reviewed.
